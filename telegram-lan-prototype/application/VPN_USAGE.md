# 可选受管 VPN 模式（开发预览）

本阶段支持在**用户已经配置并管理的 VPN**上指定 IPv4 对端，复用聊天、群消息、文件、共享目录和投屏。默认仍为 LAN 模式。应用不安装 VPN、不申请账户、不配置路由/防火墙，也不开放公网端口。

这不是公网连接服务。设备 ID/昵称仍是对端声明，应用协议没有设备密钥认证或自身的端到端加密。VPN 的身份、加密、路由和访问控制由既有 VPN/管理员承担；应用无法验证这些保证。不要把本应用端口映射到互联网。

## 启动方式

1. 先由用户/管理员建立受信 VPN。两端都需要本机 VPN IPv4、对方 VPN IPv4，以及 VPN 接口的**系统名称**。
2. 运行 `LanLink --list-network-interfaces` 查看接口名和 IPv4，或者在主菜单“网络连接诊断”查看。列表会包含非 VPN 接口，应用不会根据名称自动认定它是 VPN。
3. 在两台设备分别明确启用 VPN 模式，例如：

```text
# 设备 A，假设其已有接口为 tailscale0，VPN IP 为 100.64.0.10
LanLink --vpn --vpn-interface tailscale0 --vpn-address 100.64.0.10 --vpn-peer 100.64.0.20 --port 45870

# 设备 B，假设其已有接口为 tailscale0，VPN IP 为 100.64.0.20
LanLink --vpn --vpn-interface tailscale0 --vpn-address 100.64.0.20 --vpn-peer 100.64.0.10 --port 45870
```

Windows 的接口系统名称可能不同，请使用本机列出的精确名称；有空格的名称应加引号。示例名称和地址不能替代实际配置。每个额外设备重复一次 `--vpn-peer <IPv4>`，最多 256 个；两端都需批准对方。

4. 在“添加设备 IP”中填对方的 VPN IPv4 和实际监听端口。VPN 不使用 UDP 广播发现。
5. 先用“网络连接诊断”测试，再验收消息/群回执、文件/共享以及投屏。诊断会向对方发送普通设备握手，对方可能保存本机名称和地址；可达不表示身份已验证。

参数不会保存为全局应用设置。每次启动必须明确选择；可由用户自行在启动快捷方式中保存参数。VPN 模式未指定 `--port` 时使用固定 **45870**；指定 `0` 会拒绝启动。端口占用时直接报错，不会偷偷换随机端口。LAN 模式保留原来的默认自动分配端口（可用 `--port` 固定）。

## 应用实际实施的限制

- VPN 模式只监听指定本机 IPv4。该地址必须属于指定的正在运行接口。监听/出站使用同一策略；消息、文件下载、共享下载、投屏都绑定同一个本机源地址。
- 只允许精确列出的对端 IPv4。支持 RFC1918 私网和 `100.64.0.0/10` 内地址，**不会全局放行该网段**；其他未批准私网、域名、公网地址、CIDR 和 IPv6 都拒绝。回环/链路本地地址允许用于受控本机测试，但本身不是 VPN。
- 入站连接在读取应用数据之前检查远端地址与本机目标地址。聊天/文件/共享/投屏共用此入口，不额外打开其他监听端口。
- 每次出站前检查接口；运行中每秒复查。检测到接口消失、关闭或地址不匹配会关闭监听及包括已移交文件/投屏服务的 TCP 连接。需要恢复 VPN 后重新启动应用，不自动回退 LAN，也不会自动重连到其他本机地址。
- 已保存联系人、待发消息、文件邀请、下载票据及结果重试带有本地创建时的网络模式。回 LAN 启动或显式重新添加同一设备不会把原 VPN 待发任务改走 LAN。旧版无模式记录按 LAN 处理。
- 文件接收、共享发布及投屏确认保持原有规则。VPN 不会自动授予共享访问、文件接收或屏幕捕获权限。

**重要边界：源 IPv4 绑定不等于操作系统的强制接口路由绑定。** Qt 检查本机接口地址并绑定 socket 的源/监听地址，但不检查 VPN 隧道加密、路由表或所有包的真实入口/出口。部分 OS 有弱主机模型，也可能发生路由变化。必须由管理员按设备身份和接口配置 VPN ACL、路由及防火墙。应用没有修改这些安全设置，不能代替它们。

## 连接诊断

主菜单“网络连接诊断”显示当前模式、本机绑定地址、监听端口、实际接口观测、对端白名单、广播是否关闭及最近停止原因。刷新只读取本机状态。

“测试连接”发送受同一地址策略限制的 LanLink 握手：
- 立即拒绝：未批准 IP、非数字地址、接口不可用、监听未启动。
- 连接失败/超时：检查双方 VPN 在线、两端白名单、端口、管理员路由/ACL/防火墙。
- 有效应答：仅表示该端口运行兼容 LanLink，不能证明显示名称对应的身份或隧道安全性。

诊断不自动改变设置、不添加本地联系人、不尝试公网地址或降级路径。

## 验证及尚未完成的验收

`tests/test_networkpolicy.cpp` 使用显式的测试接口观测快照以及真实本机回环 TCP，覆盖精确白名单、100.64/10 边界、无效配置、固定端口冲突、入站拒绝、聊天 ACK、文件/共享下载、投屏、接口失效停连和跨模式重启隔离。另测旧队列数据库迁移、125 条异模式待发任务不阻塞当前模式的新消息，以及普通/共享文件下载中断时保留暂停状态。测试接口观测不由 CLI 或配置文件控制。

本执行环境禁止 Qt 使用 AF_NETLINK 枚举真实网络接口；真实接口观测测试因此标记跳过，生产代码不会因此放宽校验。**本机模拟测试不等于真实 VPN、Windows 或跨城双设备验收**。尚需用户批准并完成两地 VPN 的接口/路由/ACL、断线恢复、群逐人 ACK、大文件续传/共享撤销、慢链路投屏等验收。无公网中继、NAT 打洞、域名寻址、应用身份认证、应用 E2EE 或云离线转发。
